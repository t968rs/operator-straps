# v1.1.0 (proposed)

Since `v1.0.0`. Minor: harness bumped its minor version, so the level proposed at the start of the cycle
stands. Each branch that bumps a plugin adds its row to the table and one line per change below, tagged with
its PR number.

## Plugins

| Plugin | Was | Now |
|---|---|---|
| harness | 0.82.1 | 0.83.0 |

Unchanged: agent-watcher, arc-straps, band-line, banner-status, bubble-stamp, git-status, parallel2-lanes,
pytest-scope, session-bookmark, todo-watch, working-refs. The `superpowers-lt` entry points at its own
repository and is versioned there.

## Changes

- Feat(harness): `tdd-strapped` skill, a port of superpowers-lt `test-driven-development` with its
  `writing-good-tests.md` reference (issues #335, #131). The Verify GREEN step runs every test file the change
  reaches by name and hands a needed full-suite run to the developer, in place of the source's bare suite run;
  the bug-fix example names its test file. strap-debugging, consumer-contract-audit, the parallel2 README and
  `HARNESS_RULES.md` point at `harness:tdd-strapped`; `tests/skills/test_tdd_strapped_skill_contract.py` guards
  the standalone trigger and the scoping rules. A strap-skills round (frozen at `4bb62e633f2a`) proved three
  rules against failing baselines: a relayed skip or a deadline is no exception to test-first; a past regression
  means naming every consumer's test file, never a folder run; the code's current output never becomes an
  expected value.
- Fix(harness): strap-debugging stands alone (issue #142). Its trigger no longer waits on superpowers-lt being
  absent, its verification step runs the proving tests by file name, and check-runlogs and the
  `HARNESS_RULES.md` Troubleshooting rule load it directly instead of `superpowers-lt:systematic-debugging`;
  `tests/skills/test_strap_debugging_skill_contract.py` guards all three routes.
