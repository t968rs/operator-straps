# v1.1.0 (proposed)

Since `v1.0.0`. Minor: harness and session-bookmark bumped their minor versions, so the level proposed at the
start of the cycle stands. Each branch that bumps a plugin adds its row to the table and one line per change
below, tagged with its PR number.

## Plugins

| Plugin | Was | Now |
|---|---|---|
| harness | 0.82.1 | 0.87.0 |
| session-bookmark | 0.3.1 | 0.4.1 |

Unchanged: agent-watcher, arc-straps, band-line, banner-status, bubble-stamp, git-status, parallel2-lanes,
pytest-scope, todo-watch, working-refs. The `superpowers-lt` entry points at its own repository and is
versioned there.

## Changes

- #337 Feat(harness): `tdd-strapped` skill, a port of superpowers-lt `test-driven-development` with its
  `writing-good-tests.md` reference (issues #335, #131). The Verify GREEN step runs every test file the change
  reaches by name and hands a needed full-suite run to the developer, in place of the source's bare suite run;
  the bug-fix example names its test file. strap-debugging, consumer-contract-audit, the parallel2 README and
  `HARNESS_RULES.md` point at `harness:tdd-strapped`; `tests/skills/test_tdd_strapped_skill_contract.py` guards
  the standalone trigger and the scoping rules. A strap-skills round (refrozen at `37a95216726e` after review) proved three
  rules against failing baselines: a relayed skip or a deadline is no exception to test-first; a past regression
  means naming every consumer's test file, never a folder run; the code's current output never becomes an
  expected value.
- #337 Fix(harness): strap-debugging stands alone (issue #142). Its trigger no longer waits on superpowers-lt being
  absent, its verification step runs the proving tests by file name, and check-runlogs and the
  `HARNESS_RULES.md` Troubleshooting rule load it directly instead of `superpowers-lt:systematic-debugging`;
  `tests/skills/test_strap_debugging_skill_contract.py` guards all three routes. The README install list no
  longer offers superpowers-lt, whose TDD and debugging skills would trigger alongside the bundled ones.
- #338 Feat(harness): `writing-comments` skill (issue #317). A new Python module with more than one group of
  definitions gets canonical section dividers (a rule / title / rule banner per group, `# -- name ----`
  lines inside one) and process comments that state reasons; `comment_sections.py` prints a module's
  outline and flags dividers off the convention, at the width of the new `comments.divider_width` key
  (default 88). A strap-skills round proved the divider rule against a failing baseline.
- #339 Feat(harness): pr-sum `--level 0` (issue #268): the Summary alone, with no file descriptions, Files
  Changed table, Relocated or delta table, and no sections; `build` skips the description check at that level.
- #339 Feat(harness): pr-sum `--gh` (issue #269): after saving the `.md`, `build` writes the same markdown into
  the PR description between `<!-- pr-sum:start -->` and `<!-- pr-sum:end -->` (new `harness_lib.pr_body`),
  replacing an earlier block on a rerun and keeping text outside the markers; unpaired markers or a failed
  `gh` call is a `problem:` line that names the saved file.
- #342 Feat(add-todo, session-bookmark): optional session goal for an added TODO item (issue #282).
  `add-todo --hook retired|committed|developer` adds a `Hook:` line to the row; once the inbox drain lands the
  item, `add_todo.py hook --todo <id> --closed-by <C>` (`TodoHook` on `AddTodoRequest`) arms
  `<state_dir>/session-bookmark/hook.json`, and `add_todo.py hook --clear` removes it. The session-bookmark
  mod's new `session_hook.ts` runs `/goal <goal>` through `$.command.run` at the end of the next main-loop
  turn and stamps the switch `fired`, so the goal is set once; a refused `/goal` leaves the switch armed and
  shows one toast. `tests/mods/test_session_bookmark_hook_contract.py` pins the switch path, version and keys
  on both sides. Each closing is one the agent meets itself (`committed`: tests passed and a commit message
  drafted; `developer`: tests passed and a handoff reply), since `/goal` re-checks at every stop.
- #342 Feat(add-bookmark): `--goal <condition>` arms a free-text session goal, `--goal-todo <id> <closing>` the goal
  of a catalog item, `--goal-clear` removes the switch (`add_note.py goal`, through
  `add_todo_api.write_goal_switch`); `--remove` takes several numbers from one listing, and `--edit` takes
  several `N <text>` groups.
- #342 Fix(add-bookmark): a leading `--word` the skill does not know (`--pin`, `--todo`, a typo) prints
  `unknown flag: <word>` and the usage line and stores nothing, instead of storing a note that begins with the
  flag; a `--goal` condition leaves a developer step out entirely and the reply does not explain the omission.
  Strap round 3 (base `d818b31`, relinked from `fc72809`) proves the goal routing, the developer-free goal, multi-note `--remove` and
  `--edit`, and the unknown-flag stop; frozen at `abf003a20d2a`.
- Feat(harness): `strap.py rename <name> <new-name>` moves a frozen, unlocked strap spec to its skill's new
  name once the skill folder moved: the spec folder and the freeze ledger folder move whole (entry files
  unchanged), parts under the old skill folder or at a name-made path (contract test, models, API, driver)
  are re-pointed, the old name becomes the new one in behavior statements and scenario text, and a `rename`
  ledger entry (new `from_name` field in `FreezeLedgerEntry.schema.json`) names the old subject. Entries
  before the rename keep their tags under the old stem, and the commit-tag lookup follows a moved entry file
  (`git log --follow`). `tests/scripts/test_strap_rename.py` covers the move, the tags and the refusals.
- Change(harness, session-bookmark): the `add-bookmark` skill is renamed `bookmark` (`/harness:bookmark`;
  "add-bookmark" stays a trigger phrase). The session-bookmark mod's unreadable-notes hint and docs name the
  new command; the strap spec moved with `strap.py rename` and was refrozen on the renamed parts.
