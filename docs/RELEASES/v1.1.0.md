# v1.1.0 (proposed)

Since `v1.0.0`. Minor: harness, session-bookmark and working-refs bumped their minor versions and lap-stamp was
added, so the level proposed at the start of the cycle stands. Each branch that bumps a plugin adds its row to
the table and one line per change below, tagged with its PR number.

## Breaking changes

- #344 The `/harness:add-bookmark` command is gone: the skill is now `bookmark`, invoked as `/harness:bookmark`
  with the same flags, and no alias keeps the old name. Saying "add-bookmark" still routes to the skill. Update
  session-bookmark to 0.4.1 together with harness so its unreadable-notes hint names the live command
  (`/harness:bookmark --clear`).

## Plugins

| Plugin | Was | Now |

## Changes

- #337 Feat(harness): `tdd-strapped` skill, a port of superpowers-lt `test-driven-development` with its
  `writing-good-tests.md` reference (issues #335, #131). The Verify GREEN step runs every test file the change
  reaches by name and hands a needed full-suite run to the developer, in place of the source's bare suite run;
  the bug-fix example names its test file. strap-debugging, consumer-contract-audit, the parallel2 README and
  `HARNESS_RULES.md` point at `harness:tdd-strapped`; `tests/skills/test_tdd_strapped_skill_contract.py` guards
  the standalone trigger and the scoping rules. A strap-skills round (refrozen at `37a95216726e` after review) proved three
  rules against failing baselines: a relayed skip or a deadline is no exception to test-first; a past regression
  means naming every consumer's test file, never a folder run; the code's current output never becomes an
  expected value.
- #337 Fix(harness): strap-debugging stands alone (issue #142). Its trigger no longer waits on superpowers-lt being
  absent, its verification step runs the proving tests by file name, and check-runlogs and the
  `HARNESS_RULES.md` Troubleshooting rule load it directly instead of `superpowers-lt:systematic-debugging`;
  `tests/skills/test_strap_debugging_skill_contract.py` guards all three routes. The README install list no
  longer offers superpowers-lt, whose TDD and debugging skills would trigger alongside the bundled ones.
- #338 Feat(harness): `writing-comments` skill (issue #317). A new Python module with more than one group of
  definitions gets canonical section dividers (a rule / title / rule banner per group, `# -- name ----`
  lines inside one) and process comments that state reasons; `comment_sections.py` prints a module's
  outline and flags dividers off the convention, at the width of the new `comments.divider_width` key
  (default 88). A strap-skills round proved the divider rule against a failing baseline.
- #339 Feat(harness): pr-sum `--level 0` (issue #268): the Summary alone, with no file descriptions, Files
  Changed table, Relocated or delta table, and no sections; `build` skips the description check at that level.
- #339 Feat(harness): pr-sum `--gh` (issue #269): after saving the `.md`, `build` writes the same markdown into
  the PR description between `<!-- pr-sum:start -->` and `<!-- pr-sum:end -->` (new `harness_lib.pr_body`),
  replacing an earlier block on a rerun and keeping text outside the markers; unpaired markers or a failed
  `gh` call is a `problem:` line that names the saved file.
- #342 Feat(add-todo, session-bookmark): optional session goal for an added TODO item (issue #282).
  `add-todo --hook retired|committed|developer` adds a `Hook:` line to the row; once the inbox drain lands the
  item, `add_todo.py hook --todo <id> --closed-by <C>` (`TodoHook` on `AddTodoRequest`) arms
  `<state_dir>/session-bookmark/hook.json`, and `add_todo.py hook --clear` removes it. The session-bookmark
  mod's new `session_hook.ts` runs `/goal <goal>` through `$.command.run` at the end of the next main-loop
  turn and stamps the switch `fired`, so the goal is set once; a refused `/goal` leaves the switch armed and
  shows one toast. `tests/mods/test_session_bookmark_hook_contract.py` pins the switch path, version and keys
  on both sides. Each closing is one the agent meets itself (`committed`: tests passed and a commit message
  drafted; `developer`: tests passed and a handoff reply), since `/goal` re-checks at every stop.
- #342 Feat(bookmark): `--goal <condition>` arms a free-text session goal, `--goal-todo <id> <closing>` the goal
  of a catalog item, `--goal-clear` removes the switch (`add_note.py goal`, through
  `add_todo_api.write_goal_switch`); `--remove` takes several numbers from one listing, and `--edit` takes
  several `N <text>` groups.
- #342 Fix(bookmark): a leading `--word` the skill does not know (`--pin`, `--todo`, a typo) prints
  `unknown flag: <word>` and the usage line and stores nothing, instead of storing a note that begins with the
  flag; a `--goal` condition leaves a developer step out entirely and the reply does not explain the omission.
  Strap round 3 (base `d818b31`, relinked from `fc72809`) proves the goal routing, the developer-free goal, multi-note `--remove` and
  `--edit`, and the unknown-flag stop; refrozen at `75d50d204630` after review; round 4 (base `192b993`) re-proves it after the session-binding fix, frozen at `b92e3d247f44` and locked (ledger r4.3); round 5 (base
  `12dfb0c`) re-proves it after the review fixes, refrozen at `e10df9d1de47`.
- #344 Feat(harness): `strap.py rename <name> <new-name>` moves a frozen, unlocked strap spec to its skill's new
  name once the skill folder moved: the spec folder and the freeze ledger folder move whole (entry files
  unchanged), parts under the old skill folder or at a name-made path (contract test, models, API, driver)
  are re-pointed, the old name becomes the new one in behavior statements and scenario text, and a `rename`
  ledger entry (new `from_name` field in `FreezeLedgerEntry.schema.json`) names the old subject. Entries
  before the rename keep their tags under the old stem, and the commit-tag lookup follows a moved entry file
  (`git log --follow`). `tests/scripts/test_strap_rename.py` covers the move, the tags and the refusals.
- #344 Change(harness, session-bookmark): the `add-bookmark` skill is renamed `bookmark` (`/harness:bookmark`;
  "add-bookmark" stays a trigger phrase; see Breaking changes). The session-bookmark mod's unreadable-notes
  hint and docs name the new command; the strap spec moved with `strap.py rename` (ledger entry r3.5) and
  round 4 re-ran its greens under the new name, refroze it and locked it.
- #342 Fix(harness, session-bookmark): the hook switch is bound to the session that armed it. `add_note.py goal`
  and `add_todo.py hook` store `CLAUDE_CODE_SESSION_ID` as the switch's `session_id`
  (`add_todo_api.arming_session`), and `session_hook.ts` fires only when it matches `$.session.id()`; a switch
  with no id fires in any session. With two sessions on one checkout, the other session no longer takes the
  goal. `test_session_bookmark_hook_contract.py` pins `SESSION_KEY` on both sides.
- #342 Fix(harness, session-bookmark): review fixes. `add_todo.py hook` and `add_note.py goal --todo` share one
  catalog gate (`add_todo_api.hook_catalog`), so an unreadable or non-object catalog is refused as such by both
  writers, and `hook --clear` refuses `--todo` / `--closed-by`; the bookmark skill relays a refused catalog
  without the notes `--clear` line. `AddTodoRequest.hook` is a `Closing`. `session_hook.ts` checks and records
  its per-load guard with no await between, so two close turn ends queue `/goal` once, and the stamp-failed
  toast names `/harness:bookmark --goal-clear`. `strap.py rename` re-points path check targets without the
  word swap, prints one `swapped:` line per rewritten text field and moves planned test copies to their new
  names; a `rename` ledger entry must carry `from_name` and no other kind may; strap ledger snapshots and the
  lock gate skip ignored bytecode, as plan locks do. strap-skills round 6 (base `12dfb0c`) refroze at
  `8846c4034055`.
- #347 Feat(harness): write-plan planned registry entries (issue #346). A plan keeps each planned test's registry
  entry in `<plans>/<id>/registry_entries.json` (`{"plan": <id>, "entries": [...]}`, new
  `harness_lib.plan_registry`) instead of a "register ahead" commit to the live registry. The new
  `tests.planned_registry` key names the project's upsert command (an argv with `{entries}` and
  `{registry}`; it needs `tests.registry`): `plan.py red` applies the entries in its throwaway tree only,
  the new `plan.py register <id> <ITEM>` writes an item's entries into the live registry once the item
  copied its tests (refusing a file not yet in the checkout) and names the `review.registry_guards` to run,
  and `record` prints a `pending entry:` line for each entry still missing. `check` and `freeze` refuse a
  malformed entries file, an entry for a file neither planned nor present, and, with the key set, a planned
  test file with no entry and no live row. The entries file joins the freeze tree, so a lock guards it.
  The write-plan strap spec refroze at `7a9fc6d4bd24` (round 5) on the B9 and B11 greens, and at
  `dd34866230d4` after the review fixes.
- #347 Fix(harness): write-plan review fixes. `plan.py lock` refuses a freeze-set file (an entries file, a
  planned test) the last freeze left out; `register` refuses an item test file with no planned entry and no
  live row, and `upsert` refuses a command that exits 0 without listing every entry; the `pending entry:` hint

- #347 Fix(harness): the plan page shows blank-line paragraph breaks in item actions and decision rationales

- #348 Feat(working-refs): per-kind colors on the ccstatusline form of the line (issue #343). A plan number
  steps through the ramp 51, 45, 74, 67, 243 as its items finish (none done, or no items: 51; all done: 243;
  else step 1 + floor(3 * done / total)), an issue number is 180, another branch's name 246 and the
  punctuation 240; the TODO label colors are unchanged, and the plain `text` band-line reads is not colored.
  An item is done by its `<plans>/<id>/receipts/<ITEM>.json` outcome kind (`complete` or `closed`), else by
  its status (`COMPLETE` or `CLOSED_NO_ACTION`). The `tool.call` change check lists only the receipts folders
  of the plans on the line, and a plan id two plan files share falls back to its item statuses. `line.plans`
  carries each plan's `done` and `total`.
- Feat(lap-stamp): new mod. It times each main-conversation turn with its own clocks, the developer's prompt as
  the lap button and the turn's stop as the read-off, and stamps the clock time and lap (a wake-up adds the time
  since the last prompt) in faint right-aligned text under the reply, on the latest reply and on older replies the
  terminal redraws, matched by a fingerprint of the reply text. Every turn appends one row to the git-ignored
  `<state_dir>/lap-stamp/laps.jsonl`; `tests/mods/test_lap_stamp_config_mirror.py` pins the mirrored `state_dir`
  default. Active only where `.claude/harness.json` exists, and every hook fails open.
