# v1.0.0 (proposed)

Since `v0.7.0`. Major: the DesignEvolution catalog schema is breaking (see Breaking changes). harness bumped
its minor version; arc-straps bumped its patch version.

## Breaking changes

- `catalogs/DesignEvolutionCatalog.schema.json` is regenerated from the models and plan-bound: `plan_id` is
  required, `primary_documents` always holds the `plan`, each change lists the plan `items` it touches, and
  `category_enums` is removed. A `DesignEvolution.json` kept beside a plan's research notes no longer
  validates: move it to `<plans>/NNNN/DesignEvolution.json`, add the `plan_id`, and drop `category_enums`.
  Every level is now closed, so also drop the top-level `$schema` and `_comment`; keep only
  `highest_impact_finding`, `most_embarrassing_finding` and `lessons` under `summary` (drop
  `total_changes_cataloged`, `by_phase`, `by_issue_category` and `by_why_new_outcome_category`, which
  `DesignEvolution.counts` computes); and move each prefix key of `id_conventions` under
  `id_conventions.prefixes`, renaming `id_conventions._comment` to `id_conventions.comment`. A
  project that pinned the old catalog schema must drop the pin or copy the plugin's (schemas README,
  Migration).

## Changes

- #253 Fix(writing-docstrings): full-layout parameter format (issue #246). The tier command flags `param-format`
  (a `Parameters` item that is not `name: (type) Description` on one line, descriptions in different columns,
  a continuation off the description column; numpy-style sections included) and `underline-width` (a dashed
  underline whose width differs from its label), so a numpy-style docstring read as full is no longer kept as is. The
  convention aligns every description of a section in one column, and a continuation line starts at that column.
- #255 Fix(strap-skills): no machine paths in recorded runs (issue #254). `strap.py run` stores a run's `tree` relative to
  `worktree_root`, and `record-run` replaces the run tree, the worktree root, the project root, the main
  checkout (from a linked worktree), the harness plugin root and the home folder in a reply with `<tree>`,
  `<worktree_root>`, `<project>`, `<main>`, `<plugin>` and `~` before hashing it. Reply checks still run on
  the reply as written. Runs recorded earlier keep their absolute paths, since each reply is pinned by its
  hash.
- #255 Fix(arc-help-pages): the Python syntax section opens with `import arcpy` and
  `arcpy.ImportToolbox(r"<folder>\<archive file>")` before the call, plus a note that the toolbox alias exists
  in arcpy only after that import. The archive is named by file only, so a rebuild stays byte-identical at any
  checkout root. Pages built before 0.3.1 report `help_page_stale` until rebuilt with
  `apply_help(page, apply=True)`, and renaming the archive file stales every page.
- #257 Fix(todo-editor): the agent looks up the issue repository as `config --get todo.gh_repo`, the key
  `pr_review.py config` resolves; `todo.gh.repo`, the form `.claude/harness.json` stores, failed as an unknown
  key on every todo-edit, add-todo and sync-gh-todo run. A contract test now checks that every
  `config --get` key in an agent or skill prompt resolves against the plugin defaults.
- #261 Feat(write-plan): plan receipts and a plan-bound DesignEvolution (issue #258). `plan.py record` writes a sealed
  receipt per item beside the frozen plan (`<plans>/NNNN/receipts/<ITEM>.json`, `Receipt.schema.json`), and the
  PIP is an HTML page with a derived `live.js` sidecar that the `.gitignore` the driver writes in each plan
  folder keeps out of git. Design changes go to `<plans>/NNNN/DesignEvolution.json` through `evolution_api`;
  `record --also`, `--substitute` and `--cite` let a receipt that differs from its item (extra files, replaced
  test nodes) cite the change that allows it, and `record --sha` accepts a tag. The new user-facing
  `plugins/harness/skills/write-plan/README.md` explains the lifecycle to the developer who approves and commits.
- #262 Feat(strap-skills): strap reopen (plan 1014). `strap.py reopen <name> [--base <ref>]` opens a new round on a
  frozen spec for new behaviors: the earlier freeze moves to `rounds`, the stamp clears and `base` moves, so
  baselines read the SKILL.md at the new base. Earlier behaviors are gated again at the next freeze; a
  mechanical behavior frozen in an earlier round skips red and its planned tests rerun.
- #266 Feat(commit-msg): project canned sets and build folding (plan 1012). A new `canned_messages` key in
  `.claude/harness.json` lists the project's own canned sets (`[{"patterns": [...], "message": "..."}]`),
  tried in order before the built-in TODO and review-artifact sets by `c-msg`, `branch-commit-msg` and
  `merge-commit-msg`. `branch_commit_msg.py build` folds a canned set's file that appeared or vanished since
  capture into its canned block instead of failing coverage with `is in no commit` or `matches nothing`.
- #265 Feat(write-plan, strap-skills): freeze ledger, scoped trees and commit tags, Frozen and Locked (plan 1015).
  `plan.py freeze` and `strap.py freeze` write a write-once entry file under `<artifacts.plans>/freezes/`
  (`FreezeLedgerEntry.schema.json`), build a git tree of the scoped not-gitignored files, and tag it
  (`base/`, `freeze/` and `lock/<stem>/...`, a `-commit` tag for the commit that adds each entry, a second one
  after a rewrite); every command prints `tag:` lines and one `push:` line, and the tags stay local until the
  developer pushes them. A plan's stamp moves from the plan JSON into the ledger at its next refreeze (`check`
  prints `legacy:` until then); a strap spec keeps its stamp and gains a ledger at its next ledger write.
  `plan.py lock` and `strap.py lock` (only on the developer's explicit ask) make a frozen plan or spec Locked;
  `plan.py unlock <id> --arm REASON`, then `plan.py unlock <id>`, reopens a Locked plan for a design change,
  and `plan.py relink` and `strap.py relink` re-point a base a rebase left off HEAD's history. `check` reports
  `untagged:`, `off-history:`, `drift:` and `ledger:` lines.
- #265 Feat(harness hooks): `guard_locked.py` denies Write, Edit and the Bash and PowerShell write shapes onto a
  Locked plan's JSON and planned tests, a Locked spec's `SkillSpec.json`, `tests/` and `fixtures/`, and every
  ledger file. It runs first inside `bash_pretool.py` and inside two new dispatchers, `write_pretool.py`
  (Write|Edit, with `guard_commit_txt`) and `powershell_pretool.py` (PowerShell, with
  `powershell_allow_shapes`).
- #265 Feat(write-plan): `plan.py record` tags the tested code locally (`receipt/<stem>/<ITEM>-commit` for
  `--sha`, `-tree` for `--staged`, `.2` on a re-record), so a reset, squash or rebase no longer leaves a
  receipt naming a commit that garbage collection can drop. Receipt tags never appear in a push line. `plan.py
  new` draws a plan number above every number on any local or remote-tracking branch and in any
  `*/plan/<no>-*` tag. Read a release version with `git describe --match 'v*'`, since driver tags sit on
  main-line commits.
