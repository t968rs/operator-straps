# v1.0.0 (proposed)

Since `v0.7.0`. Major: the DesignEvolution catalog schema is breaking (see Breaking changes), and this is the
first release whose marketplace manifest carries a version (`metadata.version` in
`.claude-plugin/marketplace.json`). harness and arc-straps bumped their minor versions; the agent-watcher,
band-line, bubble-stamp, session-bookmark and todo-watch mods and banner-status bumped their minor versions; the
working-refs mod was added; the git-status, parallel2-lanes and pytest-scope mods bumped their patch versions.
Every plugin also took a patch bump for the 1.0 manifest metadata (`homepage`, `repository`, `license`).

`#251` (arc-help-pages) appears in the v0.7.0 notes but merged after the `v0.7.0` tag, so it first ships in
this release.

## Upgrading from 0.7

1. `claude plugin marketplace update operator-straps`, then update each installed plugin (`/plugin`, or
   `claude plugin update <name>@operator-straps`). arc-straps needs `harness` 0.56.0 or later; band-line and
   working-refs need `git-status`.
2. A project that keeps a `DesignEvolution.json` beside its research notes, or that pins
   `DesignEvolutionCatalog.schema.json`: migrate it as Breaking changes describes.
3. A project that pins `TodoCatalog.schema.json` under its `schemas_dir`: copy the plugin's schema (or add the
   `keyword` property to the pinned copy) before any item carries a keyword. Then run
   `todo_sync.py keywords --dry-run`, and `todo_sync.py keywords` once its guesses look right. `inbox put`
   now refuses an item that has no keyword, so the add-todo and sync-gh-todo runs draft one.
4. A project with dated `TODO_Snapshot_<YYYY_MMDD>.md` files: delete them by hand. The next render writes
   `TODO_Snapshot.html` and `todo_live.js`. `todo.snapshots.name_pattern` is still accepted, but nothing
   reads it.
5. Optional: set `scratch_folder` (the TODO inbox), `working_refs.max_chars` and `attach.auto_resolve` in
   `.claude/harness.json` (README, Configure a project).

## Breaking changes

- `catalogs/DesignEvolutionCatalog.schema.json` is regenerated from the models and plan-bound: `plan_id` is
  required, `primary_documents` always holds the `plan`, each change lists the plan `items` it touches, and
  `category_enums` is removed. A `DesignEvolution.json` kept beside a plan's research notes no longer
  validates: move it to `<plans>/NNNN/DesignEvolution.json`, add the `plan_id`, and drop `category_enums`.
  Every level is now closed, so also drop the top-level `$schema` and `_comment`; keep only
  `highest_impact_finding`, `most_embarrassing_finding` and `lessons` under `summary` (drop
  `total_changes_cataloged`, `by_phase`, `by_issue_category` and `by_why_new_outcome_category`, which
  `DesignEvolution.counts` computes); and move each prefix key of `id_conventions` under
  `id_conventions.prefixes`, renaming `id_conventions._comment` to `id_conventions.comment`. A
  project that pinned the old catalog schema must drop the pin or copy the plugin's (schemas README,
  Migration).
