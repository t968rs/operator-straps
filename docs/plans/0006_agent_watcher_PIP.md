## Decisions

- **D1** How does a layer reach the engine (`$`) when the core calls it? Chosen: `io-closures` (Core builds an `Io` object of closures over `$` (read, list, write, toast, state update) and passes that; layers never see `$`). Rejected: `dollar-param` (Layer methods take `$` and core passes it: `layer.onSettle($, run)`). Spike on 2026-11-04 (`claude plugin validate` on a two-file probe mod): `layer.viaDecl?.($)` is refused with "$ itself is passed as an argument"; an `Io` built by a core function declaration and passed to `layer.rowFields(io, ...)` validates, reported as `$.fs.read (via ioOf)`.
- **D2** Which header key names the dispatching skill, given that strap rows already print `SKILL: <skill under test>` and the strap agents read that line? Chosen: `skill-key` (`SKILL:` names the dispatching skill; strap's current `SKILL:` line is renamed `TARGET:` in strap.py, both strap agents and their init commands). Rejected: `new-key` (A new key (for example `HARNESS_SKILL:`) names the dispatching skill; strap's `SKILL:` line stays and lands in `fields`), `skill-as-is` (`SKILL:` is read as written; strap rows log the skill under test as `skill`). Developer, 2026-11-04: `SKILL:` names the dispatching skill, as #193's example reads; strap's skill-under-test line becomes `TARGET:`.
- **D3** Which prompt lines become a usage row's `fields`? Chosen: `leading-block` (The run of uppercase `KEY: value` (or `KEY=value`) lines at the top of the prompt, ending at the first line that is not one). Rejected: `anywhere` (Every column-1 uppercase key line anywhere in the prompt). Long prompts and briefs carry `SIGNAL:`-style lines in their body; only the leading block is the dispatch header.
- **D4** Mixed-case prompt keys (todo-edit and sync-gh-todo `Operation:`/`Project root:`, docstring rows `Project root:`/`Scope:`, bubble-memo `Memo:`): rename to uppercase or leave? Chosen: `leave` (Leave them; drivers and skill prose only add the D2 skill line; mixed-case lines are not captured in `fields`). Rejected: `uppercase` (Rename every key to uppercase in drivers, skill prose and the agent files that read them, so they are captured). Developer, 2026-11-04: agent prompt contracts stay unchanged; only the skill line is added.
- **D5** Which `Agent` dispatches does agent-watcher log? Chosen: `all-dispatches` (Every Agent call: defined agents, built-ins (Explore, general-purpose, Plan) and other plugins' agents). Rejected: `defined-only` (Only agents the marketplace defines (today's DEFINED_AGENTS rule)). Developer, 2026-11-03: agent-watcher "monitors and logs ALL agent dispatches".
- **D6** Which return-block form does the watcher read? Chosen: `dash-fence` (One form: the column-1 `---` fenced block with a SIGNAL line; strap runner and judge adopt it). Rejected: `accept-text-fence` (Also accept a ```text fence), `keep-no-block` (Leave strap rows at NO_BLOCK). Developer, 2026-11-03: "using the same form makes sense".
- **D7** How do layer hooks (band, Stop, prompt line, shell refresh, session-start recovery) register? Chosen: `direct-register` (register.ts calls each layer's `registerXLayer(on)` function directly). Rejected: `registry-loop` (register.ts loops over LAYERS and calls `layer.register(on)`). Spike on 2026-11-04: `layer.register?.(on)` is refused with "on is used other than as a call or an argument to a function of the module's own"; a direct `registerProbeHooks(on)` validates.
- **D8** How are `fields` values stored in the tracked usage log, given that headers carry paths (strap TREE, INIT, SPEC; bubble-memo FILES)? Chosen: `drop-path-values` (Core drops any value holding a path separator (`/` or `\`), key included; other values cut to 200 characters). Rejected: `as-written-capped` (As written, cut to 200 characters; paths enter the log), `drop-path-keys` (Core drops keys known to hold paths (TREE, INIT)). Developer, 2026-11-04: "We do not want any local OR absolute paths" in the log. A generic rule on the value catches every key, known or not; the schema rejects a separator so a row that slips one through fails validation. The cap bounds row size (local review 1123, I4).
- **D9** Which dispatches may the pr-review layer claim once any skill may print RUN_ID, AGENT_ID and AGENT_ROLE? Chosen: `refuse-foreign-skill` (identify refuses a header whose SKILL is present and not pr-review or pr-team). Rejected: `reserve-roles` (Reserve reviewer and fixer for the layer in the header convention; core logs a SKILL header before the layer claim). Review 0208 I2: today a RUN_ID + AGENT_ID + reviewer header with no PR line is claimed as pr-team. pr-review and pr-team headers carry no SKILL line, so refusing a foreign one changes nothing for them. Developer, 2026-11-04: amend and refreeze.
- **D10** How does core tell a layer-claimed run from a generic one, and how are generic runs keyed? Chosen: `claimed-by-flag` (Run.claimedBy names the claiming layer; generic runs keyed by their generated id). Rejected: `standalone-sentinel` (Keep skill === 'standalone' as the marker). Review 0208 I2: once the skill comes from the SKILL header, the 'standalone' sentinel no longer marks unclaimed runs (band takeover, leaked runs, shared RUN_ID entries dropped early). Developer, 2026-11-04: amend and refreeze.
- **D11** What does core do with a header value that fails its pattern or rule? Chosen: `fallback-keep-raw` (Fall back (standalone, other, generated id, type name, null pr); a `<plugin>:` skill prefix is stripped; the raw value stays in fields under D8). Rejected: `widen-patterns` (Widen the schema patterns to the values real headers carry), `drop-row` (Reject the row (as first planned)). Review 0208 I2: a rejected row breaks D5. Developer, 2026-11-04: strip the plugin prefix (`harness:strap-skills` logs `strap-skills`), schema skill pattern unchanged; PR fills the top-level pr; RUN_ID and AGENT_ID fall under the no-paths rule.
- **D12** How does a layer member read and write mod state through `Io`? Chosen: `per-key-closures` (One Io closure per state key (runs, active, failures, phase5, missing)). Rejected: `generic-atom-io` (Generic `read(atom)` / `update(atom, change)` on Io). TASK-3 lane, 2026-11-04: `claude plugin validate` refused the generic form: "the state library's read takes a source the scan can read: a reference whose plugin and key are string literals". Cost: core declares the pr-review `phase5` and `missing` keys; a second layer with state edits core (README Layout section).
