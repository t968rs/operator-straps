Decisions

  • D1 Where does the AutoResolve dataclass live? Chosen: config (harness_lib.config, beside the attach.auto_resolve key that builds it). Rejected: driver (the a-w commands folder, with the config holding plain dicts). One frozen type serves the config load and the driver; the config stays typed and hashable like CannedSet.
  • D2 Which checkout's .claude/harness.json supplies attach.auto_resolve? Chosen: target (load_config(project_root(target checkout)) when that checkout holds .claude/harness.json, else load_config(main_worktree(target checkout))). Rejected: worktree (load_config(project_root(worktree))). The rules govern what lands on the target branch, and the target checkout is the project the developer configures; an untracked harness.json never reaches a worktree. A target branch checked out in a linked worktree (a collector) lacks that untracked file too, so the main checkout supplies it there; a tracked harness.json is present in every checkout, so the target's own copy wins. test_untracked_main_checkout_rules_apply_to_a_target_in_a_linked_worktree pins it.
  • D3 How does attach_worktree.py split as it grows? Chosen: split3 (attach_worktree.py (CLI, preconditions, flow, removal), attach_merge.py (snapshot, overlap, backup, trial merge, rules, land), attach_resolve.py (state file, rebase loop, --continue, --abort)). Rejected: single (one module past 290 lines). The spec leaves the split to the builder and allows it by concern; three concerns, each under the 50-line function rule, keep each file readable.
  • D4 What does --continue do when no rebase is in progress (after a race refusal)? Chosen: restart (rerun the flow from the snapshot (spec item 2) with patch_base set to the target_head the finished rebase went onto, and land against the current target HEAD). Rejected: reland (re-snapshot and land the diff from the new target HEAD to the resolved tree). A diff from the new target HEAD to a tree built on the old one reverts the late target commit; measuring from the old target_head carries only the worktree's work. DesignEvolution entry records it.
  • D5 What exit code does a successful --abort return? Chosen: zero (0, with one report line). Rejected: one (1, as a refusal). The abort did what was asked; 1 stays the refusal code and 2 the resolution stop.
  • D6 How do rule patterns match paths? Chosen: fnmatchcase (fnmatch.fnmatchcase over the repo-relative POSIX path). Rejected: fnmatch (fnmatch.fnmatch, case folding on Windows). The same rule set must land the same files on every OS; case folding on Windows would widen a rule there only.
