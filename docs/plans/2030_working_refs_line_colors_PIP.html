Decisions

D1 Where does a plan's done share come from?

Chosen

  • mod-reads-receipts the mod reads <plans>/<id>/receipts/<ITEM>.json itself

Unchosen

  • live-js the mod reads the page's generated <id>/live.js
  • harness-file the harness writes a progress file per plan

developer pick (approach A, spec Approaches): receipts are committed and write-once, so the color is right on every checkout; live.js and a harness file are absent until rebuilt

D2 Which way does the plan gradient run?

Chosen

  • fade bright while active, dim as items finish

Unchosen

  • brighten dim at the start, bright when done

developer answer: a plan nearing its archive recedes

D3 Which renderer gets the colors?

Chosen

  • ccstatusline-only the ccstatusline form (statusText) only

Unchosen

  • both ccstatusline and band-line

proposed in conversation, not corrected; band-line keeps its subtle one-color form

D4 Does an item closed without action count as done?

Chosen

  • closed-done complete and closed count as done

Unchosen

  • complete-only only complete counts

proposed in conversation, not corrected; matches plan_enums.DONE
