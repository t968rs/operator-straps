Decisions

D1 #272: what shape do single-note changes take?

Chosen

  • remove-edit add_note.py gains `remove N` and `edit N TEXT`; the skill gains `--remove N` and `--edit N <text>`; each prints the numbered list after the change

Unchosen

  • remove-only `remove N` / `--remove N` only; an edit is remove then add
  • separate-skill a new remove-bookmark skill over the same script

Developer's answer, 2026-11-18.

D2 #279: what branch scope does a new note get by default?

Chosen

  • current-branch add records the checked-out branch; `--standing` stores none; a note without a branch (old files, detached HEAD) is standing

Unchosen

  • standing notes apply on every branch unless `--branch` is passed

Developer's answer, 2026-11-18. The bookmark never hides a note, so a wrong default costs a marker, not a lost note; the field is optional, so NOTES_VERSION stays 1.

D3 #305: how is the notes view that needs no model turn invoked?

Chosen

  • session-bookmark-arg an argument on the existing command: `/session-bookmark notes`; bare `/session-bookmark` keeps printing the saved bookmark

Unchosen

  • bookmark-notes-command a second mod command, `/bookmark-notes`

Developer's answer, 2026-11-18. The mod's `command.run` handler answers with text and no model turn (bookmark.ts:240-243).

D4 #279 remedy (c): where does the rule 'a note from another branch is confirmed with the developer before it is applied or skipped, never dropped silently' live?

Chosen

  • bookmark-header one hint line under `## Session Notes` in the bookmark, printed only when a note carries another branch, plus the same sentence in the add-bookmark SKILL.md

Unchosen

  • header-and-rules the bookmark-header option plus a line in plugins/harness/rules/HARNESS_RULES.md, which every session reads at start
  • none the `now on` marker alone; no rule text

Developer's answer, 2026-11-18.

D5 #204: what does a mod do when another mod ends or reroutes the session.compact chain before it?

Chosen

  • fallback-next-prompt session-bookmark and todo-watch also observe the compaction row on `session.append` (door `compaction`, main loop); session-bookmark then attaches the bookmark as context on the next prompt.submit when its own session.compact handler did not run for that compaction; todo-watch re-forces its TODO_SYNC line

Unchosen

  • fallback-append-now as fallback-next-prompt, but session-bookmark appends the bookmark at once through `$.session.append` (door `note`), so a mid-turn auto-compaction is covered before the next prompt
  • document-only no code change; each mod's README names the ordering limit

Developer's answer, 2026-11-18.
