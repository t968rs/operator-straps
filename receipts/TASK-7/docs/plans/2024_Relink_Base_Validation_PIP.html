Decisions

D1 When does relink run the anchor and sweep check at the candidate base? check reads them at base_commit once an item is done (claims_rev, plan.py:351-357), and freeze requires them at the base while no item is done (base_claim_problems, plan.py:456-467).

Chosen

  • D1A Always: a relinked base must satisfy both readers, so a base that breaks a later freeze --refreeze is refused as well as one that breaks check

Unchosen

  • D1B Only when an item is done (claims_rev of the book view is not None), as issue 313 proposes; with no item done the relink writes unchecked and a later refreeze reports the problems through base_claim_problems

Developer choice 2026-11-17: always check. freeze requires the anchors at the base while no item is done, so a relinked base must satisfy both readers.

D2 Does relink get an override flag that writes the base despite failing claims?

Chosen

  • D2A No override: the refusal is final; a base with no valid counterpart stays off-history, which check only warns about

Unchosen

  • D2B --force: write anyway and print each at-base problem as a warn: line; the plan then fails check until a write plus freeze --refreeze re-anchors it (unlock first on a Locked plan); adds a test and a minor harness bump

Developer choice 2026-11-17: no override. The anchors quote the old base, which its tag keeps reachable; off-history: only warns.

D3 What does relink without --to print when patch-id finds no counterpart (a merge commit has no patch id, freeze_git.py:282-283)? Today it ends with 'pass --to REF', which invited the guessed --to in the plan 2023 incident.

Chosen

  • D3A Reword: drop 'pass --to REF'; say a base squashed or merged away has no counterpart and its off-history: warning is the end state, and that --to is only for a commit known to hold the base's code

Unchosen

  • D3B D3A plus the cause: name 'a merge commit has no patch id' when the base has two or more parents (git rev-list --parents -n 1); adds a test with a merge-commit base
  • D3C Keep the message: TASK-1's check already refuses a bad --to; TASK-2 is dropped

Developer choice 2026-11-17: drop the --to hint and name the off-history: end state.

D4 strap.py relink (strap_lock.py:465-483) has the same unchecked --to and the same 'pass --to REF' hint; a strap edit spec's base feeds its baseline SKILL.md (strap.py:706). Is it in scope?

Chosen

  • D4A Plan relink only; file a TODO for strap relink (it has no anchors or sweeps to check)

Unchosen

  • D4B Also make strap relink refuse a candidate base without the spec's SKILL.md (edit mode) and reword its patch-id hint; adds an item over strap_lock.py and strap.py

Developer choice 2026-11-17: plan relink only; strap relink is tracked separately.
