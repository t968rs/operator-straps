Create harness_lib/catalog_lock.py (standard library only, generic: names no catalog). Constants WAIT_SECONDS=10.0, WRITE_STALE_SECONDS=60.0, LEASE_STALE_SECONDS=1800.0. LockError(RuntimeError). Body JSON {pid, host (socket.gethostname()), owner, mode 'write'|'lease', acquired (time.time()), token (secrets.token_hex(8), on write locks and leases alike)}. hold(path, owner, lease=None, wait=None) is a contextmanager: with lease set, the file must hold a lease whose token matches (else LockError naming 'no lease' or 'token', at once, no wait) and the body runs without touching the file; without lease, create the file with os.open(O_CREAT|O_EXCL|O_WRONLY), retrying with random jitter (20-120 ms) until wait (None reads the module's WAIT_SECONDS at call time, so a test can patch it) runs out, breaking a stale holder first; on timeout raise LockError naming the holder's owner, mode and age. The finally removes the write lock file only when its body still carries this hold's token (read, compare, unlink), so a holder that was broken never deletes its successor's lock. acquire_lease(path, owner, wait=None) -> token (same create/retry/stale rules; a second lease waits and refuses naming the first). release_lease(path, token) removes it; a wrong token raises LockError naming 'token'. break_lock(path) -> Optional[dict] removes any lock and returns its body. read_holder(path) -> Optional[dict]. Staleness of a write lock: same host -> not pid_alive(pid), or age > LEASE_STALE_SECONDS (the ceiling against a reused pid); a live same-host holder is never broken by WRITE_STALE_SECONDS, since a hold spans add_items, render and check (Decided 11) and a git grep reference scan (Decided 16). Another host, or an unreadable body (age by mtime) -> age > WRITE_STALE_SECONDS. Lease -> age > LEASE_STALE_SECONDS only. pid_alive(pid): POSIX os.kill(pid, 0) (ProcessLookupError False, PermissionError True); Windows ctypes WinDLL('kernel32', use_last_error=True) OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION=0x1000) + GetExitCodeProcess == STILL_ACTIVE(259), CloseHandle; a failed OpenProcess with ctypes.get_last_error() == 5 (ERROR_ACCESS_DENIED: an elevated or other-user process) is alive, any other failure dead; never os.kill on Windows. Breaking a stale lock goes through break_if_unchanged(path, observed) -> bool: under an O_EXCL '<lock>.break' guard file (itself stale after WAIT_SECONDS by mtime; a busy guard means another breaker is at work, so retry), re-read the body and unlink the lock only when it still equals the observed stale body; otherwise return False and leave it. Two breakers that read one stale body therefore never remove the fresh lock one of them created. Functions under 50 lines. Copy the planned test file first.
