# parallel2-lanes

Companion mod for the harness `parallel2` skill. It reads the run state the `parallel2.py` driver writes
(`<main checkout>/<state_dir>/parallel2/<target-slug>.json`, briefs in
`<main checkout>/<state_dir>/parallel2/<target-slug>/<lane>.md`) and never writes it. The target slug is the
target branch with every character outside `[A-Za-z0-9._-]` replaced by `-`, so `feat/x` writes `feat-x.json`.

## Lane spawns

An `Agent` call whose prompt opens with a dispatch row's `Brief: <path>` line, for a lane the run state
records, starts:

- with the brief text first in its prompt (the session's prompt, `Brief:` line included, follows), so the lane
  spends no turn reading the brief;
- on the lane's planned model. A call that named another model is rewritten to the plan's, with a toast;
- in the lane's worktree as its working directory, for an implement lane.

Forks, teammates, resumed agents, workflow agents, an implement lane with no live worktree (still
`planned`, or `cleaned`) and any prompt whose brief or run state does not read pass through unchanged. The mod finds the run from the brief path alone, so it needs no configuration key.

## Lane band

Once a lane agent has been spawned, a band above the prompt draws one line per run, lanes grouped by wave:

```
parallel2 feat-x: w1 parser dispatched (running), tokens staged (returned) · w2 io planned
```

The status is the driver's (`planned`, `dispatched`, `staged`, `cleaned`); `(running)` and `(returned)` mark
the lane agents this session started. The band draws above whatever the mods beneath drew and yields to a
survey; a run whose state file is gone (`parallel2.py cleanup` removed it) drops out.

## Hooks

| Hook | Does |
|------|------|
| `agent.spawn` | Rewrites a lane spawn as above, records the started agent's lane and rereads its run; a resumed lane agent reads `running` again. |
| `turn.complete` | Marks a lane agent's lane `returned`; rereads the runs at every turn end. |
| `tool.call` (Bash, PowerShell) | After a command naming `parallel2.py` returns, rereads the runs. |
| `ui.render` `AbovePrompt` | Draws the lane band. |

## State

`$.state['parallel2-lanes']` (contract: `types/index.d.ts`):

| Key | Meaning |
|-----|---------|
| `spawned` | The lane each spawned lane agent runs, by agent id. |
| `agents` | Each spawned lane's agent phase (`running`, `returned`), by `<stateFile>#<laneId>`. |
| `runs` | The runs seen this session, as the band draws them. |

## Known limitations

- Only a prompt whose first non-blank line is `Brief: <path>` is a lane spawn. A dispatch row pasted whole
  puts its `lane=... model=...` line first, so the spawn passes through: no brief inline, no model rewrite,
  no worktree.
- The spawned agents and runs live in per-session state. A new or resumed session draws no band for a run
  in flight until it spawns a lane agent, and a lane agent started in an earlier session never reads
  `(running)` or `(returned)`.
- `(returned)` means the agent's run ended, an interrupted run included; it says nothing about whether the
  lane's work landed. The phase is kept per lane, so a lane dispatched twice reads `(returned)` as soon as
  either agent ends.
- Runs are reread only after a lane spawn, at a turn end, and after a Bash or PowerShell command naming
  `parallel2.py`; a driver run from another terminal or session shows at the next turn end.
- Each run is one line, cut at the terminal width rather than wrapped.

## Checks

```
claude plugin validate --strict <mod folder>
claude plugin test <mod folder>
```

## Loading

```
claude plugin marketplace add t968rs/operator-straps
claude plugin install parallel2-lanes@operator-straps
```

For development, a `CLAUDE_CODE_PLUGIN_DIRS` entry in the user-level `~/.claude/settings.json` `env` block (or
`claude --plugin-dir <folder>` for one session) loads the folder with hot reload and replaces the marketplace
copy of the same-named mod. The variable is one string, `;`-separated on Windows: append to its existing value
rather than replacing it.

`.claude-plugin/types/` is generated by the engine on load and git-ignored; `tsconfig.json` extends it.
