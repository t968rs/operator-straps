Decisions

D1 What shape does the HTML snapshot take?

Chosen

  • D1A One fixed page TODO_Snapshot.html in todo.snapshots.dir, rewritten by every render, plus a todo_live.js stamp beside it; an open page polls the stamp and reloads itself when it changes

Unchosen

  • D1B A dated TODO_Snapshot_YYYY_MMDD.html per render, as the markdown snapshots were
  • D1C A static shell page whose script draws the whole table from a full-catalog sidecar

Developer delegated every design call for issue 288 (2026-11-17 session: no brainstorming input). The issue asks for one page instead of a new document per render. Drawing the table in Python keeps one renderer (D1C would duplicate it in JS), and the stamp gives the plan page's live reload without a second renderer. The T2 header stays the first line.

D2 What happens to todo.snapshots.name_pattern?

Chosen

  • D2A Keep the key and its load-time check so existing configs validate; render, init and T2 stop reading it; the schema and README call it legacy

Unchosen

  • D2B Remove the key (a breaking config change)
  • D2C Keep T2 reading the newest dated markdown when the page is absent

Developer delegated every design call for issue 288 (2026-11-17 session: no brainstorming input). Removing a key is a breaking change across the marketplace; a T2 fallback to stale markdown would keep warning on files nothing rewrites.

D3 What does the Summary block above the table hold (issue 280)?

Chosen

  • D3A Catalog counts: items, per status and per kind as badges, trackers and close candidates

Unchosen

  • D3B A second list of the top-N headings with their badges

Developer delegated every design call for issue 288 (2026-11-17 session: no brainstorming input). The top-N table is already one screen; the counts give the whole catalog at a glance, which the table cannot.

D4 Where does an item's prose go (issue 278 direction)?

Chosen

  • D4A A <details> in the Item cell: summary, proposed change, decision question and ranking reason, folded by default

Unchosen

  • D4B Nowhere: the table carries only the row fields

Developer delegated every design call for issue 288 (2026-11-17 session: no brainstorming input). Keeps the tabular format at a glance while the catalog prose is one click away instead of a JSON lookup.

D5 Does render keep the snapshot files out of git?

Chosen

  • D5A No: the project decides; the TODO canned commit message covers the page and the stamp

Unchosen

  • D5B Yes: render writes a .gitignore in the snapshots folder, as plan live.js does

Developer delegated every design call for issue 288 (2026-11-17 session: no brainstorming input). Projects already commit snapshots (the canned TODO set names them); this repository ignores them in its own .gitignore.
